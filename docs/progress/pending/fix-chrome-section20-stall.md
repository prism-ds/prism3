## (2026-11-27) — test:chrome bounds the mode control's settle, so a page that stops drawing fails by name (#4612)

**What changed.** `settleModes` in `apps/studio/test-chrome.mjs` now runs inside one `within` (`STEP_MS`, 30s). That's the shared wait before every mode pick: `pickMode`, `chooseMode` and their 12 callers. Every read in it is a `page.evaluate` waiting on `requestAnimationFrame`, and a `page.evaluate` has no timeout of its own. The two plain `page.evaluate`s on the same path run in a `within` too: `chooseMode`'s place read, the first thing every mode pick does, and `modeLook`'s read (review on #4642). The Type-edits case in section 20 now calls `watchStalls` on its page, so a recurrence names where the page stopped. A new arm, `#4612`, is registered in `packages/engine/test-arms/`.

**Where #4612 waited.** CI stopped section 20 at the 600s watchdog with "the last check it reached: type: setting body back to Inter …". The next step is `chooseMode(page, 'dark')` → `pickMode` → `settleModes`, and the stall comes before `modeLook`, whose `ok()` would have moved the last check. Every Playwright action and `waitForFunction` on that stretch throws at 30s or less. Three kinds of wait had no bound: `settleModes`' frame waits, which hang on an **idle** page (scripts run, no frame is drawn), and two plain `page.evaluate`s, `chooseMode`'s place read and `modeLook`'s read, which hang on a **busy** page (the main thread runs no script). An earlier draft of this entry said the frame waits were the only ones; the review found the two plain reads, and a forced busy page still stopped at CI's exact watchdog line until they were bounded. It is the same family as #4342, whose CI captures read busy.

**This is diagnostic: it bounds the stall; it does not remove its cause.** A stall on this path, idle or busy, now fails fast and by name, and #4612 stays open for the root cause, which is #4342's. A page that stops producing frames can't be settled by any test-side wait: the fit the settle waits for runs in a frame. What changes is how a recurrence reads. It now fails the case in about 60s: 30s for the bound, 3s for the frame probe, and up to 30s for `stallWhere` on the watched page. It names the step ("the mode control (settleModes) did not settle within 30s; the page renders no frame; …", or `chooseMode: the place …` / `modeLook: the mode control's fit …` on a busy page) and gives the page's state, instead of holding the shard for 600s and naming the check before.

**Reproduced.**
- **Forced:** main's code, with the page's `requestAnimationFrame` held just before `chooseMode(page, 'dark')`, stops at the watchdog with CI's exact line: `✗ section 20: no progress for 90s … the last check it reached: "type: setting body back to Inter returns the persisted brand to its bytes"`. With this change, the same condition fails `S6.2 Type edits: the case stopped at a step that threw — the mode control (settleModes) did not settle within 30s; the page renders no frame; the main thread still runs a script, so it is idle and no frame is being produced; …`.
- **Natural:** the Type-edits case repeated in-process, Inter, JetBrains Mono and Playfair Display hidden by a fontconfig `rejectfont` (CI's runner has none of them), 4 processes beside 2 CPU burners on 4 cores. Results: 0 stalls in 48 cases; 0 in 48 with the Google Fonts stub reply delayed 0–3s; then, with this change and the page watched, 2 page stalls in 308 cases. One was a `persisted` read that never answered (watchdog), the other a `waitForFunction` timing out at 30s. Neither was in `settleModes`, and neither left a native stack: the headless shell carries no symbols. The delayed-reply runs also failed "Add face stages Roboto" 4 times. That came from the injected delay, which also slows the Roboto lookup, and does not happen with CI's immediate stub.

**Mutation (fails by name).** `within` dropped from `settleModes` → `✗ #4612: a mode-control settle on a page that draws no frame fails by name within its bound, not at the 600s watchdog (15000ms: still waiting at the 15s guard: the settle has no bound)`. The arm holds a bare page's frames and asks for a 3s settle. Its own 15s guard is what lets the mutation fail there rather than at the watchdog. The arm's busy case makes a bare page busy with a looping timer and asks `chooseMode` and `modeLook` for their reads on a 3s bound each; MUTATION_BUSY_PLACEHOLDER

**Trap.** `within`'s label carries no issue number (its header says why): the arm's number lives in the `ok()` label only.
