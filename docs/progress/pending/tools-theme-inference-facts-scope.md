## (2026-11-27) — File facts 0.2: a scan takes a scope and carries an inventory (#2853 Q5 A)

**What changed.** The owner's Q5 A on #2853 asked for a small tools PR before the read-only capture jobs run on files A–E: scope and inventory in `scan-script.ts` and `file-facts.ts`, with the facts format at `0.2`. `packages/engine/file-facts.ts` gains `scopePages`, the one place the scope rule lives. It takes the whole file, the selection on the current page (or the current page when nothing is selected, Q1 A), or an explicit list of page ids or layer ids. The report gains `scope` (kind, how it was given, the root ids in file order, the pages that hold it) and `inventory` (the spike's §5.3 step 2 table: one row per visible top-level frame, section or component set, a section's children in turn). `coverage.pages` now counts the pages in scope. The plugin adapter takes a `ScopeChoice` and loads only the current page for a selection. `scan-script.ts print <n>` requires `--scope file|selection|<ids>`. The capture jobs are in the PR body.

**Decisions inside the lane.**
- `--scope` is required, with no default. A capture that silently took the whole file, or the selection, would be the wrong row and still join cleanly.
- An explicit list names pages or layers, not both, and an id the file does not hold refuses the scan by name (`ScopeError`). A scope that quietly lost a frame would read as a smaller file.
- Ids are reported in file order, not selection order, so one selection always scans to the same bytes.
- The inventory reports the five most-used solid fills per row instead of the spike's `topHue`. A hue family is an interpretation, and the facts report proposes nothing, so the seed computes hue from these.
- `explicitModes` is a sorted list of `{ collectionId, collection, modeId, mode }`, not an object keyed by collection name, because two collections can share a name.
- A 0.1 report still reads: `FACTS_FORMATS_READ` lists 0.1 and 0.2, and `seedFromFacts` and `compare.ts` refuse any other id by name. 0.2 only adds fields and narrows `coverage.pages` to the scope, so a 0.1 report is a whole-file scan with no inventory.

**Read-only, proven.** `apps/plugin/test-file-facts.ts` already failed on any node write. It now also wraps the host (`figma`, `figma.variables`) in a logging Proxy with stubs for `setCurrentPageAsync` and similar methods, so a scan that switches pages or touches the file fails `<label>/the scan wrote nothing to the file`. Every scoped scan runs through that check. Mutations, each failing by name: a write slipped into the selection path (`current.selection = …`), a `setCurrentPageAsync` slipped into the ids path, a `setPluginData` slipped into `scopePages`, the selection loading every page, ids kept in selection order, the nested-cover rule dropped, the empty-selection fallback dropped, the background read from the bottom paint, and names leaking into the fingerprint.

**Limit, documented in the header.** The usage walk starts fresh at each scope root, so a root nested inside an icon, a button or an instance does not inherit that ancestor's role or `inInstances` count. Scope to pages, sections or frames.
