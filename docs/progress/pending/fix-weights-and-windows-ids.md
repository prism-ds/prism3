## (2026-11-24) — Per-mode weights take 1–1000, and a Windows-invalid brand id is refused where its files are written (#4214)

The last two items of the #4214 hygiene bundle, both decided on the issue on 2026-11-20.

**Weights (item 5, decision A).** #3954 widened the global `typography.weightRoles` to whole numbers in [1, 1000], DTCG's fontWeight range, because variable fonts take any weight in it. Per-mode `modeLevers.<mode>.weights` kept [100, 900] in both the schema and `brandTheme`, so a mode could not move a weight as far as the brand could set one. Both now take [1, 1000]. This only accepts more input. The per-mode value keys a `core.font.weight.<n>` primitive exactly as the global one does, so the #3871 alias path already covers 1 and 1000; the new arm builds both on the dark weight roles with every alias resolving.

**Windows-invalid ids (item 6).** The id pattern lets `CON`, `nul`, `a?b`, `a|b` and `a*b` through, and no Windows checkout can hold the files they name. **A note on the decision's letter:** the owner's comment reads "→ A" but describes the triage's option B ("leave the published schema alone, and refuse such ids only where a file is written, with a named error"). This builds the description, which is also the triage's recommendation. If A's schema refusal was meant, it is a pattern change on top of this, not a rework.
- `emit-dtcg.ts` gains `windowsInvalidName` (the characters `< > : " | ? *` and the controls, and the device names CON, PRN, AUX, NUL, COM0–9 and LPT0–9 with ¹ ² ³, as the part before the first dot in any case) and `fileInDir`, the #3875 guard lifted out of `emitTheme` with that check added. Every platform refuses such an id, so a brand that writes on one machine writes on all of them.
- `cli.ts`'s other writes, the fidelity report and the three component-spec files, now go through `fileInDir` too, the technical half of item 6 that waited on #4271. Each is checked before the first write.
- `export_theme` writes files as well, so it refuses the same ids as an `isError` result, checked over every name before the first write. The result's shape is unchanged: `{ error }`, as every other refusal there.
- The schema and `brandTheme` still accept these ids, and `validate_brand` still calls them valid; an arm holds that.

**Tests.** `test.ts`: the weight edges in engine and schema, 0 and 1001 refused by name, and the old D-typo(f) arms moved to the new edges; a table of 20 refused and 9 accepted ids written from Windows' rule, not read from the function; `emitTheme` refusing `nul` and `a?b` with no directory made; the CLI refusing `CON` through `fail()` with nothing on disk; and a source arm that every `writeFileSync` in `cli.ts` takes a path bound from `fileInDir`. `mcp-test.ts`: `export_theme` refuses `CON`, `nul` and `a?b` with no directory made, while `validate_brand` still accepts them. Each mutation (the ranges back to 100/900, the check out of `fileInDir`, the fidelity report back to `resolve(...)`, the check out of `export_theme`) fails arms by name.

DRAFT wording for the owner's voice pass: "'CON.tokens.json' is not a file name Windows can write: 'CON' is a reserved device name. Use a brand id that isn't CON, PRN, AUX, NUL, COM0–9 or LPT0–9; nothing was written." and the character variant.
